# 文件在线预览 — 需求分析与方案设计

> 归档日期：2026-09-09
> 适用版本：kkFileView 4.4.0 + file-upload-service 1.0.0
> 关联文档：[实现方案与落地代码](./02-实现方案与落地代码.md)

---

## 一、需求背景

### 1.1 业务目标

项目已实现基于策略模式的多存储后端文件管理服务（LOCAL / FTP / MinIO），支持文件的上传、下载、删除、查询。现需在此基础上集成 **kkFileView 4.4.0** 实现浏览器端文件在线预览，使用户无需下载即可直接查看 Office 文档、PDF、图片、压缩包等常见格式。

### 1.2 核心需求

1. **统一预览入口**：无论文件存储在 LOCAL、FTP 还是 MinIO，均可通过同一套 API 获取预览链接
2. **最小代码侵入**：不破坏现有策略模式架构，复用已有的 download 能力
3. **正常路径格式**：预览 URL 不暴露内部 bucketName 等存储细节
4. **可扩展**：支持水印、页码控制等 kkFileView 扩展参数

## 二、kkFileView 核心原理

### 2.1 工作机制

kkFileView 是一个基于 Spring Boot 的文件在线预览服务，其核心工作流程：

```
调用方 → 提供文件 URL → kkFileView 下载文件 → 格式转换 → 返回可预览的 HTML/PDF/图片
```

### 2.2 预览 API

kkFileView 所有预览能力统一汇聚到 `onlinePreview` 入口：

```
GET {kkFileView地址}/onlinePreview?url={Base64编码的文件URL}
```

**关键参数：**

| 参数 | 说明 | 示例 |
|------|------|------|
| `url` | 文件下载地址的 Base64 编码（必填） | `Base64("http://xxx/report.pdf")` |
| `fullfilename` | 当下载流无后缀时，指定文件名让 kkFileView 识别类型 | `report.pdf` |
| `watermarkTxt` | 预览水印文本 | `机密文件` |
| `page` | 指定预览页码 | `1` |
| `filePassword` | 加密文件密码 | `123456` |

### 2.3 对接核心约束

kkFileView 服务器必须能通过网络访问到文件 URL。这意味着：
- 文件 URL 不能是本地路径（如 `C:\xxx`）
- 文件 URL 不能是需要认证才能访问的接口（除非拼接 Basic Auth 参数）
- 文件 URL 最好包含文件后缀，或通过 `fullfilename` 参数显式指定

## 三、当前项目现状分析

### 3.1 现有架构

```
┌─────────────────────────────────────────────────┐
│              FileController (REST API)           │
│  POST /upload, GET /download, DELETE /{id}, ...  │
└──────────────┬──────────────────────────────────┘
               │
               ▼
┌─────────────────────────────────────────────────┐
│        RequestUploadProcessor (Facade)          │
│  请求解析 → 类型校验 → 策略路由 → 结果组装        │
└──────────────┬──────────────────────────────────┘
               │
               ▼
┌─────────────────────────────────────────────────┐
│       UploadStrategyFactory (Factory)           │
│  自动注册所有 @Component 策略                     │
└──────────────┬──────────────────────────────────┘
               │
       ┌───────┼────────┐
       ▼       ▼        ▼
┌──────────┐ ┌──────┐ ┌──────────┐
│  Local   │ │ FTP  │ │  MinIO   │
│ Strategy │ │Strat.│ │ Strategy │
└──────────┘ └──────┘ └──────────┘
```

### 3.2 现有下载接口

```
GET /api/files/download?fileKey=xxx&uploadType=local
```

- Content-Disposition: `attachment`（触发浏览器下载）
- Content-Type: 固定 `application/octet-stream`
- 通过策略模式路由到对应存储实现获取文件字节流

### 3.3 架构约束分析

| 约束 | 影响 | 应对策略 |
|------|------|----------|
| 三种存储的文件不直接对外暴露 HTTP URL | kkFileView 需要一个可访问的 URL 来拉取文件 | 新增 `previewFile` 端点统一对外提供文件流 |
| 下载接口返回 `attachment` 头 | kkFileView 需要 `inline` 方式获取 | 新建独立端点，不影响原有 download 语义 |
| 下载接口 Content-Type 固定为 octet-stream | kkFileView 依赖 Content-Type 识别文件类型 | previewFile 端点按后缀动态设置 Content-Type |
| 部分下载流 URL 无文件后缀 | kkFileView 无法识别文件类型 | 通过 `fullfilename` 参数显式传递原始文件名 |

## 四、方案对比选型

### 4.1 方案 A：前端直调模式（轻量后端）

```
前端 → 后端获取预览URL → 前端直接打开 kkFileView 页面
                              ↓
                    kkFileView → 后端 /previewFile 端点 → 存储层
```

**实现思路：**
- 后端提供 `/api/files/previewUrl?id=xxx` 返回 kkFileView 完整预览链接
- 后端提供 `/api/files/previewFile` 以 inline 方式提供文件流给 kkFileView 拉取
- 前端拿到 URL 后 `window.open()` 直接打开

### 4.2 方案 B：后端代理模式（重量后端）

```
前端 → 后端 /preview → 后端下载文件 → 后端调 kkFileView API → 返回预览内容
```

**实现思路：**
- 后端下载文件后通过 kkFileView 的多文件上传接口提交
- 后端代理返回预览 HTML 内容
- 前端通过 iframe 嵌入预览

### 4.3 六维度对比

| 维度 | 方案 A（前端直调） | 方案 B（后端代理） |
|------|-------------------|-------------------|
| **实现复杂度** | 低（约 100 行新代码） | 高（300+ 行，需处理 kkFileView 上传 API） |
| **网络要求** | kkFileView 需能访问后端 URL | 同左，且后端需中转全部文件流 |
| **大文件性能** | 优（kkFileView 直接拉流，不经前端） | 差（文件内容全经后端中转） |
| **安全性** | 中（previewFile 端点可加鉴权） | 高（文件不对外暴露） |
| **扩展性** | 好（水印/页码等参数直接拼 URL） | 差（需额外封装上传逻辑） |
| **架构契合度** | 完美（复用策略模式，三种存储统一走 previewFile） | 需大改（引入文件上传到 kkFileView 的逻辑） |

### 4.4 最终决策

**选择方案 A（前端直调模式）。**

决策理由：
1. **最小落地**：仅需新增 1 个 Service + 2 个 Controller 端点，约 100 行代码
2. **性能最优**：文件流不经过前端中转，kkFileView 直接从后端拉取
3. **完美复用**：三种存储策略通过策略模式统一路由，previewFile 端点零冗余
4. **官方推荐**：kkFileView 官方文档推荐的接入方式即为 URL 直传
5. **扩展友好**：水印、页码等参数只需拼接 URL 即可，无需改动后端逻辑

## 五、架构流程图

### 5.1 完整调用时序

```
┌──────────┐                          ┌──────────┐                          ┌──────────────┐
│  前端     │                          │  后端     │                          │  kkFileView  │

└────┬─────┘                          └────┬─────┘                          └──────┬───────┘
     │                                     │                                     │
     │  ① GET /previewUrl?id=abc123        │                                     │
     │ ──────────────────────────────────→ │                                     │
     │                                     │                                     │
     │  ② 返回 kkFileView 预览 URL         │                                     │
     │ ←────────────────────────────────── │                                     │
     │                                     │                                     │

```

### 5.2 URL 构建流程

```
文件 ID
  │
  ├─→ 查找 FileInfo (fileKey, storageType, originalFilename)
  │
  ├─→ 构建 previewFile URL:
  │     http://127.0.0.1:8080/api/files/previewFile
  │       ?fileKey=xxx
  │       &uploadType=local
  │       &fullfilename=report.pdf
  │
  ├─→ Base64 编码
  │
  └─→ 拼接 kkFileView URL:
        http://127.0.0.1:8012/onlinePreview
          ?url={Base64编码结果}
          &watermarkTxt=xxx (可选)
```

## 六、支持的文件格式

kkFileView 本身支持的主流格式（取决于其内部转换器配置）：

| 分类 | 格式 |
|------|------|
| Office 文档 | doc, docx, xls, xlsx, ppt, pptx |
| 文档 | pdf, txt, csv, xml, json, html |
| 图片 | png, jpg, gif, bmp |
| 压缩包 | zip, rar |
| 音视频 | mp4, mp3 |
| 其他 | 更多格式参考 kkFileView 官方文档 |

> 注意：实际支持的预览格式取决于 kkFileView 服务端安装的转换器（LibreOffice、ImageMagick 等）。
